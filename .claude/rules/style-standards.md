# Style standards

Every agent that changes markup or CSS follows these. `DESIGN.md` is the visual system and `PRODUCT.md` the product context; this file is the checklist. A reviewer or `ux` reports a breach as a finding.

- Tailwind v4, CSS-first. Source of truth is `src/app.css`.
- Use design tokens (`--brand`, `--surface`, `--ink-muted`, etc.), not raw colours. Status tokens: `--success`, `--warn`, `--danger`, `--info`. A good value stays in the palette (`--success` is `--brand`); colour leaves it only to warn (`--warn` copper, `--danger` raspberry). Use the tokens, never a green or red of your own.
- `<style lang="postcss">` + `@reference "…/app.css"` in every component that uses `@apply` or tokens.
- **Design work goes through the Impeccable skill** (`.claude/skills/impeccable`, `/impeccable`). `PRODUCT.md` holds the product context and `DESIGN.md` the visual system; read both before UI work and update `DESIGN.md` when the system changes. The vendored skill is excluded from prettier/eslint; update it with `npx impeccable update`, never by hand.
- **One visual system, every page** (`DESIGN.md`): a data console on the violet palette, after a pinned reference (Podscan.fm). Reuse its pieces, don't invent values:
  - **Type.** `.display` (Inter Tight 700) for titles; the system UI stack for everything else, tracked tight (`letter-spacing: -0.02em` on `body`). Card headings 18px 600; page titles 30–60px. Field names use `.label` (small, muted, sentence case); numbers use `tabular-nums`.
  - **Containers.** `.card` (1px `--border`, 12px radius, `--surface-raised`) is the one container; never nest cards. Lists inside a card separate rows with `--border` hairlines. Tinted plates use `--brand-wash`. Status callouts (the verdicts) use the `--token-soft` fills with the solid token for text.
  - **Actions.** `.btn` + `.btn--brand` (one per view, the main action), `.btn--ink` (secondary filled), `.btn--ghost` (beside a filled one), `.btn--pill` for the nav. Inline links use `.link`; secondary links in a row (Methodology, a source's domain) use `.chip`.
  - **Highlights.** A term inside a sentence (the landing's voice) is `<mark class="highlight tone-*">`: status tones `pos` / `mid` / `neg` / `neutral` for values, source tones `bechdel` / `um` / `ddd` / `tmdb` for source names. In data views, values stay `Badge`s.
  - **Status.** `Badge` (`$lib/components/ui/badge.svelte`) with a tone from `$lib/media/utils/tones.ts` (`bechdelTone`, `umTone`, `safetyTierTone`, `shareTone`), which mirror `verdict.ts`. Don't hand-roll pills.
  - **Sources.** Each source has an icon and a violet shade (`--src-bechdel`, `--src-um`, `--src-ddd`, `--src-tmdb`) used together in a `.disk` (set `--hue`, optional `--disk` size) or as a stat-line icon. Bechdel `ri-chat-3-fill`, Unconsenting Media `ri-flag-2-fill`, Does the Dog Die `ri-alarm-warning-fill`, TMDB `ri-film-fill` / `ri-group-fill`.
  - **Radius and elevation.** 8px buttons, 12px cards and inputs, 9999px pills and the logo. Hairlines separate; `--shadow-md` for dropdowns, `--shadow-float` for one floating surface per page, `--shadow-brand` on the brand button's hover.
  - **Sticky header.** The 64px header is sticky: anchored sections set `scroll-margin-top: 5rem`, sticky columns `top: 5rem`.
  - Spacing uses the `xs/sm/md/lg/xl` tokens or the 4px grid. Focus rings come from the base layer.
- **Avoid.** No kicker/eyebrow above a heading; no uppercase letter-spaced labels; no colored `border-left`/`border-right` over 1px; no gradients; no hover lift or glow; no pulsing badges; no `→`/`↗`/`←` text glyphs as icons (Remixicon or plain words); no decorative imagery; no new hues outside the violet shades and the status tokens. Icon disks only for sources and metric sections, where the shade identifies the source. Every element must carry information or an action.
- **Metric status rows share one marker language.** Per-item status lists (Bechdel criteria ladder, UM flags) use a `1.375rem` round marker holding a glyph or step number, rows `flex items-center gap-sm text-sm` with `padding-block: var(--spacing-xs)`. Active states fill the token's soft tint (`--warn-soft`, `--success-soft`, or `color-mix(in oklab, var(--brand) 14%, transparent)`) + solid-token glyph; inactive states are a transparent marker with a `--border` hairline and an `--ink-muted` glyph. **Pick the token semantically:** brand for neutral progress (Bechdel: the rating already reads from the section's status badge, so no status tone), `--warn`/`--success` only where a per-item value is a real signal (UM concerns / `noRape` reassurance). When adding a new metric checklist, copy this marker — see the `.criterion-*` block in `movie/[movieId]/+page.svelte` and `.flag-*` in `umMetricSection.svelte`, and `docs/architecture.md`, Shared marker pattern.
- **Data legibility beats colour-coding.** In dense tables (cast/crew representation), keep numeric values in high-contrast `--ink`/`--ink-muted` and carry colour identity in bars + swatches — never colour the digits themselves. Gender series use `--seg-female` / `--seg-male` / `--seg-nonbinary` / `--seg-unknown` (unknown is `--border-strong`, a step darker than the `--surface-sunken` track); split bars are fully rounded with a 2px gap between segments.
