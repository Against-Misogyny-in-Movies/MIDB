# Docs standards

Before they work, agents read:

- `AGENTS.md` (`CLAUDE.md` is a link to it);
- the rules in `.claude/rules/`;
- their agent file;
- `docs/phases/STATUS.md`;
- the live plan;
- the sections of `docs/architecture.md`, `DESIGN.md` and `PRODUCT.md` that their task touches.

They find those sections through `docs/INDEX.md` and read one with `pnpm docs:section <file> "<heading>"`. Every line in those files costs context on every run.

These docs say what is true now. History is in git: a commit message says what changed and why, and `git log -- <file>` finds it. A reviewer reports a breach as a finding.

## Current state, not history

- When a change supersedes a rule, a design or a plan step, rewrite the passage so it states the new rule. Do not append "was / now", "replaces PR N", "previously", or a dated note under the old text.
- No dated "built" or "implemented" tags on headings or list items. A thing that is not built says "Not built." in one line.
- Keep an authority stamp on a rule the user set, short: "(user instruction, 2026-11-12)". It cites who decided, not how it was reached.
- Say each rule once, in the file that owns it (`.claude/rules/authority.md` names the owners), and point to it from elsewhere. Do not copy a rule into an agent file, a phase note or a plan.

## Facts the code owns

- Do not write down a number or a list the code holds: verdict thresholds, row counts, rate limits, cache TTLs, test counts, branch names. Point to the file that holds it (`src/lib/media/utils/verdict.ts`, `src/lib/server/http/cache.ts`).
- Cite a doc by file and section heading, never by line number, because lines move with every edit. Write the heading's words (`docs/architecture.md, Caching policy`). Rename a heading and its citations together.

## The index

- `docs/INDEX.md` is generated by `pnpm docs:index`. It is the only doc with line numbers. Do not edit it by hand.
  - Run the command after adding, removing or renaming a doc or a heading, or after any doc edit that moves lines.
  - `scripts/docs/__tests__/index.spec.ts` fails when it is stale.
- A new doc agents should read goes in a folder the index lists (`groups` in `scripts/docs/index.ts`).
- A long doc keeps `##`/`###` headings for each topic, so the index can point into it. A bold run-in label is not a heading.
- When one section grows past a few thousand tokens and only some tasks need it, split it into its own file and leave a one-line pointer where it was.

## `docs/architecture.md`

The living snapshot of the code: the file map, each module's job, and the structural patterns. Update it in the same change as any structural change (`.claude/rules/code-standards.md`, Making a change), following the rules above.

## `docs/phases/STATUS.md`

- The rules header, then one row per phase. A note is at most about 200 characters: the date, and only what is still open (a review not run, deferred work).
- **Open items:** one line per thing still to do, grouped by area. Delete the line when it is done. Do not move it to a "done" list.
- **Standing decisions:** one line per user decision that still constrains later work, with its date. Delete it when the work it constrained is finished and nothing later depends on it.
- No dated sections, no "Built / Decided / Checked" blocks, no fixed review findings, test counts, timings or commit hashes. Those go in the commit message and the final report to the user.

## Plans

- **Where plans live.** Every implementation plan, design note and multi-step proposal is saved as `docs/plans/plan-<short-name>.md`, not left only in chat.
- **While it is live.** A plan stays live while its work is open. Its phases are the rows of `docs/phases/STATUS.md`.
- **When it is done.** Delete the plan; git keeps it. A citation of it in code or a live doc must then point to the doc that owns the behaviour instead (`docs/architecture.md`, `DESIGN.md`, the rules).
- **Older plans.** `docs/plans/done/` holds plans finished before this rule. They are history: they are not read for current rules, and they are not cited.
- **Prompts.** A paste-once prompt for a new session is not committed. Give it to the user in the report, or put it in the scratchpad.
